* Prerequisites

+ [[https://bun.sh/][Bun]], the version in =package.json='s =packageManager=
+ Info-ZIP's =unzip=, for =src/lib/zip.test.ts=, which reads the zips it makes back with it
+ Python 3 and [[https://python-pillow.org/][Pillow]], only to redraw =static/og.png= (=scripts/og.py=)

* Setup

#+begin_src sh
git clone https://github.com/NasreddinHodja/pad.nassu.online.git
cd pad.nassu.online
bun install
bun run dev      # http://localhost:5173, database in data/pad.db
#+end_src

=PAD_DB= names the database file; it's =data/pad.db= when unset.

The browser's crypto only runs on =localhost= or HTTPS: from a phone on the LAN, =adb reverse tcp:5173 tcp:5173= and open =localhost:5173= on it.

* Scripts

| Command                 | Description                                   |
|-------------------------+-----------------------------------------------|
| =bun run dev=           | Dev server                                    |
| =bun run build=         | Production build (adapter-bun), into =build/= |
| =bun run check=         | Svelte and TypeScript type checking           |
| =bun run check:watch=   | The same, on every change                     |
| =bun run lint=          | Prettier and ESLint check                     |
| =bun run format=        | Auto-format with Prettier                     |
| =bun test=              | Tests, with =bun:test=                        |
| =bun run test:e2e=      | End-to-end tests in Chromium (Playwright)     |
| =python3 scripts/og.py= | Redraw =static/og.png=, the link preview      |

Building loads the server code, which opens a database: give it a throwaway one, as CI and the =Dockerfile= do (=PAD_DB=$(mktemp -d)/pad.db bun run build=). The build runs with =bun build/index.js=; [[file:docs/guide/install.org][Installing pad]] lists the environment it takes. =SOURCE_DATE_EPOCH= makes two builds of one commit the same bytes, as the release's are (=vite.config.ts=).

=scripts/bench/= measures what a server carries; each script's header says how to run it, and the results are in [[file:docs/architecture/capacity.org][Capacity and limits]].

* Before a pull request

#+begin_src sh
bun run format
bun run lint
bun run check
bun test
#+end_src

CI ([[file:.github/workflows/ci.yml][ci.yml]]) runs lint, type checking, the tests and a build on every push to =main= and every PR against it.

A change to the database's tables is a new step at the end of =MIGRATIONS= in =src/lib/server/schema.ts=; a released step is never edited.

Commit messages follow [[https://www.conventionalcommits.org][Conventional Commits]].

* Tests

=bun test= runs every =*.test.ts= under =src/=. =src/test-setup.ts= (preloaded by =bunfig.toml=) gives them an in-memory database and stands in for =$app/env=, since they run outside SvelteKit.

=e2e/= drives the production build in Chromium with Playwright (=bun run test:e2e=): it builds, then serves =build/= on port 5591 with a fresh database in the temp directory. It covers the editor's save loop, with the server made slow, failing or 429 per request through =page.route= (the save after a pause, saving again after a slow save, retries and =Retry-After=, saving on hide and on navigation, and a poll that shows another browser's write but never overwrites unsaved edits), and whole flows: claim, reload, unlock from a second browser, lock, a read-only link, and export's zip. Any console error, uncaught exception or CSP violation fails a test, and every page it visits is checked with axe for WCAG 2.1 A and AA violations. It uses =/usr/bin/chromium=; =CHROMIUM_PATH= points elsewhere, or set it empty and run =bunx playwright install chromium= for Playwright's own.
