#+TITLE: The browser's side: memory and CPU

What pad costs the browser that opens it, measured on 2026-10-11, against two references: a bare page with a plain =<textarea>= holding the same text (the floor: what Chromium itself needs to show it), and other sites, light and ordinary, loaded the same way. Goal (AUDIT.org section 17): the least memory and CPU the features allow, on desktop and on phones.

* How it's measured
+ The graphs are drawn from the raw results by =scripts/bench/client/graphs.ts=.
+ Chromium 153 (Arch package), headless unless a table says otherwise, on the author's desktop. "Mobile" is Chromium's emulation: a Pixel 7's viewport and user agent, touch, the CPU slowed 4×. It is not Android: a phone's memory pressure, which makes the collector run sooner, isn't reproduced.
+ Memory is PSS (each process's private pages plus its share of shared ones), read from =/proc/<pid>/smaps_rollup=, summed over Chromium's processes of a kind (the renderers, which run the page; the GPU process; the browser process). "Above blank" is minus the same profile's renderers on =about:blank=, measured first in each run.
+ "At rest": 1.5 s after the action, two forced garbage collections, then read. What a tab keeps while you look at it.
+ "Peak": the highest of the renderers' PSS, sampled every 20 ms from the action's start (a submit, a click, the first key) until its result shows.
+ Each run is a fresh profile. One run per cell unless the table says otherwise: differences under ~10 MiB are within noise.
+ The roots, seeded through pad's own =api.ts= (=scripts/bench/client/seed.ts=), so their pads are sealed as a browser seals them:
  + /average/: 186 pads, 477,255 bytes of text, shaped like the author's own root (=capacity.org=: half under 437 bytes, 90% under 2,992), its root pad 249,000 characters (6,388 lines).
  + /max/: the quota, 5,000 pads, 15.3 MB of text, its root pad 524,224 characters (512 KiB).
+ Scripts: =scripts/bench/client/= (=drive.ts= memory, =cpu.ts= CPU, =floor.ts= the bare textarea, =sites.ts= other sites, =typing-profile.ts= where typing's memory goes, =costs.ts= requests and paint). Raw results: =memory-results.jsonl= there (2026-10-11), =results-2026-10-12/= (the night run below) and =results-2026-10-12-evening/= (the evening run, with its =run.sh=) and =results-2026-10-12-export/= (Export).
+ The 2026-10-12 run (=run-all.sh=, 01:39–02:37, headless only, one run per cell) compares three builds: /old/, the caret as committed (=requestAnimationFrame= every frame); /cheap/, the per-line caret of the working tree forced on, which is what Firefox and Safari ran (since removed, see Typing); /native/, the working tree as is, where Chromium draws the block caret itself (=caret-shape: block=). =load.log= has the load every 15 s: the 1-minute load passed 2 only from 02:18:53 to 02:19:54 (peak 3.56), during /cheap/'s max-root typing, its busiest process the benchmark's own Chromium.
+ Keys are sent as a keyboard sends them (=Input.dispatchKeyEvent=), not =Input.insertText=: 100 characters at the end of the 512 KiB bare textarea took 94.8 s with =insertText=, 5.6 s with key events, spellcheck on or off (=typing-path.ts=). The slow path is CDP's, not Chromium's editing.
+ The 2026-10-12 evening run (21:49–22:14, headless) compares /head/, the last commit, with /now/, the working tree: the poll's ETag and the batch export, the JS caret already gone (Chromium draws its own). Both against copies of one fresh seed, same counts as above. =costs.ts= two runs each, alternating; the near-target cells three runs each on /now/. The 1-minute load stayed at or under 0.92.

** Export (2026-10-12, evening)
Max root, the page's renderer and the browser process, PSS above the moment before the click, sampled every 50 ms by =export-pss.ts= (no tracing: memory-infra dumps added 46 MiB in Chromium's tracing service and more in the page). Three runs each, each build with its own copy of the seed:

| Build                              | Renderer         | Browser        | Seconds |
|------------------------------------+------------------+----------------+---------|
| /now/: batches, deflated           | +105.2 to +111.3 | +22.8 to +26.4 | 4.6–4.9 |
| /fix/: /now/ with fewer copies     | +94.5 to +100.4  | +24.1 to +24.5 |     4.7 |
| /store/: /fix/, stored, no deflate | +79.9 to +97.1   | +27.7 to +28.3 |     0.8 |
| /nozip/: /fix/, fetch and decrypt  | +63.7 to +70.8   | +10.7 to +12.5 |     0.8 |

+ Fetching and decrypting 16 MB a batch at a time is most of it, +64–71, before any zip: the ≤ 40 target isn't reachable this way. It becomes ≤ 100, met by /fix/.
+ /fix/: =loadMany= hands export the decrypted bytes (no string and back), as views of the batch, the zip takes them uncopied, and =crc32= walks them by index. V8's sampled JS allocation over the export: 135.8 → 113.7 MiB, the builtin =next= 28.7 → 8.3 (=crc32='s =for…of=).
+ Deflating is most of the time: one =CompressionStream= a file, 3.9 of 4.7 s. Storing instead would export in 0.8 s, in a zip as big as the text (15.3 MB against deflated; the deflated size isn't measured).
+ The browser process holds the finished zip for the download.

+ The theme (7fd4137): put on once a load, not reset to the default between one theme and the next; a marble already drawn goes straight on, and while one is drawn the last stays, so a drag no longer blanks it at each colour. The picker's script time didn't move (16–17 ms for the 60).
+ Moves between pads (0a7a277): the list's ETag is a hash of its body; the tab keeps the root's names and the pads opened (≤ 1 Mi characters), dropped on lock. A save into the root used to re-seal the pad's name, so the next move downloaded the list again; a save now sends the name only for a new or emptied pad (e2e "saving a pad that exists doesn't change the root's list": list answers on four moves after saves, =200, 304, 200, 304= before, =304= ×4 after).

* Known costs, from reading the code
Checked against the code (AUDIT.org section 17 has the full list, with what's still to measure):
+ =Pad.svelte:134=: every 5 s the whole pad is downloaded and decrypted, while the tab is visible and nothing is unsaved; the server sends =no-store= and no ETag. Measured: 2.9 MiB a minute on the average root (Requests, above). Fixed (b75f53c): the version is the ETag, 304 while current, and the poll slows to 30 s with the window in the background.
+ =caret.ts:113-129=: a =requestAnimationFrame= loop every frame while a field has focus. Gone with the JS caret.
+ The Argon2 chunk (37 KB, =hash-wasm=) is loaded by the read-only link page, which never derives a password. Fixed (b99defa, Fixes below).
+ =theme.ts:76=: a PNG data URL kept for every colour pair the picker passes through. Fixed (7fd4137): the last two.
+ =[...path]/+page.svelte=: every move between pads unmounted and remounted the editor twice, loading the pad and every name twice (found by the e2e tests). Fixed by 8595472: one list and one pad a move (=costs.ts=). The editor still remounts once per pad (={#key path}=, so nothing typed in one shows in the next), so a move fetched the list again (22,992 bytes on the average root, 613,009 on the max) and the pad, though nothing changed. Fixed (0a7a277, Fixes below): both are asked by version, 304 when unchanged.
