#+TITLE: Overview
#+OPTIONS: ^:{}

SvelteKit on Bun (=@sveltejs/adapter-bun=), one SQLite file through =bun:sqlite=. Pages render on the server; everything about a pad's text happens in the browser.

* Routes

| route                              | file                                     |
|------------------------------------+------------------------------------------|
| =/=                                | =src/routes/+page.svelte=: open a path   |
| =/<path>=                          | =src/routes/[...path]/=: the gate or the editor |
| =/_/<root>/auth/<action>=          | claim, unlock, change password, lock     |
| =/_/<root>/pads=, =/_/<root>/pads/<id>= | list, read, write, delete sealed pads |
| =/_/<root>/s/<link>/<path>#<key>=  | a read-only link's pages                 |
| =/_/<root>/shares/<link>=, =/_/<root>/pads/<id>/shares= | make, read, revoke, list read-only links |

=/<path>='s load (=+page.server.ts=) normalises the path (redirecting =a//b/= to =a/b=) and returns only the root's state: =open=, =locked= or =unlocked=, and its salt. The page then shows:

+ =Gate.svelte= to claim or unlock the root, when the server or the browser lacks what it needs: an unlock cookie on one side, the keys in IndexedDB on the other;
+ =Gate.svelte= in =password= mode, for =?password=;
+ =Pad.svelte= otherwise, with =Finder.svelte= under it, =Share.svelte= when its header's *share* is pressed, =ThemePicker.svelte= for a root's *theme* and =Delete.svelte= for its *delete*.

* The editor

=Pad.svelte= loads the pad and the root's list of paths, decrypts both, and keeps =saved=, the text the server has as far as it knows. Typing schedules a save 600ms out; blur, a hidden tab and navigating away save at once. Only one save runs at a time. A failed one retries after 5 seconds. Every 5 seconds, if nothing is unsaved, it reloads the pad and takes the server's text if it changed, keeping the selection. An empty pad is deleted rather than saved, so it drops out of its parent's list.

*export* (=export.ts=) lists the root's pads with their sealed sizes, refuses past 64 MiB before fetching any, then loads the pad and those under it four at a time, and writes them into a zip in the browser (=zip.ts=: deflated by =CompressionStream=, no zip64).

*theme* (=theme.ts=) sets the root's three colours on =<html>=; =layout.css= mixes the rest from them, and the marble is redrawn in the background and ink2 on a canvas. =[...path]/+page.svelte= applies it on every page of the root, the gate's included, from what this browser last saw (=localStorage=, which =app.html= also reads before the first paint), then from the root's copy. Locking or deleting the root forgets it here.

* Database

=src/lib/server/db.ts=, =auth.ts=, =shares.ts= and =theme.ts=; =trash.ts= marks, reclaims and purges. =PAD_DB= names the file (=data/pad.db= in dev). WAL mode.

+ =sealed= :: one row per pad: its root, =id= (the HMAC of its path), =name= (its path, encrypted), =data= (its text, encrypted), =updated_at=, =deleted_at= (when it was emptied or its root deleted).
+ =roots= :: one row per claimed root: salt, SHA-256 of =auth=, the encrypted root key, =deleted_at=, =theme= (its colours, encrypted; null until one is picked).
+ =unlocks= :: one row per browser per root it unlocked: SHA-256 of the cookie's token, when it was made, when it was last used.
+ =devices= :: one row per browser per root it has ever unlocked: SHA-256 of the device cookie's token, when it was last seen there. Kept through locking; gone after 180 days unseen.
+ =shares= :: one row per read-only link: its random =id=, root, =pad= (the pad's id), =sealed_key= (the link's key, encrypted under the root's), =data= (the copy, encrypted under the link's key), =created_at=.

Emptying a pad sets its =deleted_at=; saving it again clears it. Deleting a root sets the root's and its live pads' to one time, later than any of its pads already emptied, and drops its =unlocks=; unlocking it clears the root's and those pads'. A marked pad's links 404, as do a deleted root's. A request runs a purge at most hourly: whatever was marked more than 30 days ago goes, a root with its pads, links, =unlocks= and =devices=. Claiming a deleted root purges it first.

Rate limits and wrong-password counts are in memory (=limits.ts=, =auth.ts=): a restart clears them.

* Deployment

=deploy/pad.service= runs the build as a sandboxed systemd service on =127.0.0.1:5512=, behind Caddy (=deploy/Caddyfile=), which sets HSTS, =nosniff=, =Referrer-Policy: no-referrer= and =Cross-Origin-Opener-Policy=, and keeps no access log. The app sets the =Content-Security-Policy= itself (=vite.config.ts=), with a nonce per page. =deploy.sh= lints, checks, tests, builds, uploads and restarts.
